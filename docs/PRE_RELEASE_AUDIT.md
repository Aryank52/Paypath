## Section 1: Architecture & Core Philosophy
- **STATUS:** VERIFIED & HARDENED
- **EVIDENCE:** Architecture strictly implements the unidirectional pipeline:
  `USER INTENT -> PROPOSAL -> POLICY CHECK -> PAYPAL TRANSACTION -> INTELLIGENCE -> MONITORING -> ISSUE -> POLICY + RAG -> AI REASONING -> POLICY ENGINE -> HUMAN APPROVAL -> PAYPAL ACTION -> INDEPENDENT VERIFICATION -> AUDIT LOG`.
- **TEST:** End-to-end lifecycle verified in `test_complete_paycore_and_reclaim_lifecycle`.
- **RESULT:** Deterministic governance guarantees that AI is advisory only; financial mutations require policy pass and independent verification.
- **REMAINING RISK:** None in core architecture.

## Section 5: Authentication, MFA & Session Revocation
- **STATUS:** VERIFIED & HARDENED
- **EVIDENCE:** 
  - JWT tokens carry unique `jti` identifiers.
  - `/logout` endpoint registers `jti` in revocations table, immediately invalidating tokens.
  - RFC 6238 TOTP MFA supported with QR URI and 6-digit challenge code verification.
- **TEST:** `test_auth_session_revocation` and `test_mfa_adversarial_flow`.
- **RESULT:** Replaying revoked tokens returns HTTP 401; MFA flow enforces challenge gating before issuing access tokens.
- **REMAINING RISK:** In-memory revoked token cache persists across requests; production deployments should bind to Redis for multi-instance clusters.

## Section 6: Authorization & Role-Based Access Control (RBAC)
- **STATUS:** VERIFIED & HARDENED
- **EVIDENCE:** Protected administrative endpoints (`/merchants`, `/policies`, `/publish`) enforce `require_role(UserRole.MERCHANT_ADMIN, UserRole.PLATFORM_ADMIN)`.
- **TEST:** `test_rbac_merchant_operations_denial`.
- **RESULT:** Authenticated standard customers (`USER` role) receive `403 Forbidden` on all merchant operations.

## Section 7: Password Reset & Single-Use Tokens
- **STATUS:** VERIFIED & HARDENED
- **EVIDENCE:** Password reset issues high-entropy cryptographically random tokens stored in database with expiration and `is_used` booleans.
- **TEST:** `test_password_reset_replay_defense`.
- **RESULT:** First reset succeeds; immediate replay with the identical token returns `400 Bad Request ("Invalid or expired reset token")`.
- **REMAINING RISK:** None. Reset tokens expire automatically after 1 hour.

## Section 8: Insecure Direct Object References (IDOR) & Tenant Isolation
- **STATUS:** VERIFIED & REMEDIATED
- **EVIDENCE:** Both transaction detail (`GET /transactions/{id}`) and event timeline (`GET /transactions/{id}/events`) strictly filter on `Transaction.user_id == current_user.id`.
- **TEST:** `test_idor_transaction_access_prevention`.
- **RESULT:** User B querying User A's transaction receives `404 Not Found`, completely mitigating horizontal privilege escalation and resource enumeration.
- **REMAINING RISK:** None. All resource queries enforce user tenant ownership checks.

## Section 11: Financial Invariants & Refund Boundaries
- **STATUS:** VERIFIED & REMEDIATED
- **EVIDENCE:** 
  - Rejects negative or zero refund amounts (HTTP 422/400).
  - Rejects currency mismatches (HTTP 400).
  - Enforces cumulative refund caps (`amount <= remaining_balance`).
  - Pre-evaluates idempotency keys to ensure replay returns cached outcomes without duplicate debits.
- **TEST:** `test_financial_invariants_and_refund_boundaries` and `test_refund_amount_tampering_boundaries`.
- **RESULT:** Full mathematical safety across multi-stage refunds. Replaying same idempotency key with altered amount raises `409 Conflict`.
- **REMAINING RISK:** None.

## Section 17: File Upload Security & Magic Byte Validation
- **STATUS:** VERIFIED & TESTED
- **EVIDENCE:** File upload pipeline strictly inspects the first 32 binary bytes to confirm true magic signatures (JPEG `\xFF\xD8\xFF`, PNG `\x89PNG`, PDF `%PDF`).
- **TEST:** `test_magic_byte_validation_rejection` and `test_valid_file_upload`.
- **RESULT:** Malicious files disguised with fake `.jpg` extensions are rejected with `400 Bad Request ("File signature does not match image format")`.
- **REMAINING RISK:** Upload storage currently targets local filesystem `backend/uploads/evidence`; production should stream to S3/GCS with presigned URLs.
